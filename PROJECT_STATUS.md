## Supplier catalog import pipeline
- Empty supplier CSV template: `catalog/products.csv`; Arabic columns are name, code, section, price, description, size, and product-image URL/name.
- `tools/import_catalog.py` validates the exact CSV headings, required name/code/section/image fields, unique product codes, approved store sections, and original image sources.
- Local image names must resolve to actual files under `android-app/app/src/main/assets/products/`; remote image links must use HTTPS. Missing images, HTTP links, path traversal, duplicate codes, and unknown sections are rejected rather than replaced with placeholders.
- Automated tests cover empty templates, valid local/HTTPS images, duplicate codes, missing images, HTTP links, unsafe paths, unknown sections, and idempotent storefront script injection.
- The empty CSV keeps the product grid empty. No supplier products, prices, or replacement images were invented.

## Functionality and remaining gaps
- Cart state and favorites are persisted locally on the device.
- Cart supports adding an available product, quantity changes, item removal, and a WhatsApp order-message handoff that states cash on delivery and asks the store to confirm stock, price, and delivery cost. Sending the message does not mean an order has been accepted.
- The supplier catalog is not populated, so cart/favorites/order flow cannot yet be exercised against actual store products.
- There is no product API, inventory/price backend, customer account service, or server-side checkout/payment processing.
- The signing certificate is self-issued by the store, not a Google Play-issued certificate. Signature verification is not a malware-safety guarantee; sideloaded installation can still trigger Play Protect warnings.
- No device-level installation test has been performed in this run.
